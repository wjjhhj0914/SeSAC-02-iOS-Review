## 2. 함수와 옵셔널

* 함수의 반환값(`return`)
  * `func 함수명() -> 타입`: "이 함수를 실행하면 해당 타입의 결과물(껀덕지)이 남는다"는 뜻.
  * `return` 키워드는 값을 반환함과 동시에 함수를 종료시키는 역할.
* 옵셔널과 추출
  * `randomElement()`: 배열이 비어있을 수 있기 때문에 결과값이 옵셔널(`Optional`)로 나옴.
  * `?? ""`: 결과가 `nil`일 경우 빈 문자열을 기본값으로 사용(Nil-coalescing).
  * `shuffled()` vs `shuffle()`: 반환값이 있으면 원본을 유지하고 새로운 배열을 생성, 없으면 원본 자체를 변경.

```Swift
  if myTextField.text?.isEmpty {
    print("글씨를 아무것도 안 써서 추가할 수가 없어요!")
  } else {
    movieList.append(myTextField.text!)
    print(movieList)
  }

  if myTextField.text!.isEmpty {
    print("글씨를 아무것도 안 써서 추가할 수가 없어요!")
  } else {
    movieList.append(myTextField.text!)
    print(movieList)
  }
```

#### 왜 여기서 `!`를 붙이면 에러가 사라질까?

`myTextField.text`의 타입은 `String?`(옵셔널 스트링)이다. 텍스트필드에 값이 없을 수도 있기 때문이다. 하지만 `isEmpty`는 옵셔널 타입에서는 바로 사용할 수 없고 일반 `String`에서만 사용할 수 있다. 그래서 `!`를 붙여서 "이건 절대 nil이 아니니까 일반 문자열로 취급해!"라고 강제로 깨뜨려주는(Force Unwrapping)이다.

#### `isEmpty`가 `== ""`보다 왜 더 나은 방법일까?

* 성능적인 측면: `== ""`은 실제로 빈 문자열을 하나 생성해서 두 값을 비교하는 과정을 거치지만, `isEmpty`는 문자열의 길이가 0인지만 체크하므로 훨씬 빠르고 효율적이다.
* 가독성: "값이 빈 문자열과 같은가?"보다 "비어있는가?"라고 묻는 것이 코드의 의도를 더 명확하게 전달한다.


## 3. 데이터 포맷팅 (날짜와 숫자)

* Date & DateFormatter
  * `Date()`는 영국 표준시(UTC) 기준이므로 한국 시간과는 차이가 있음.
  * `DateFormatter`는 통해 시간차(Timezone)와 표현 방식(Format)을 동시에 해결해주는 함수.
  * `yyyy-MM-dd`: 대소문자 주의. `yy-M-d` 이렇게 하나씩 작성하면 26-1-8 라고 뜸.
* NumberFormatter & formatted()
  * 금액 표시시 `12,300`처럼 쉼표를 넣을 때 필수.
  * iOS 15 이상에서는 `value.formatted(.number)`로 더 간편하게 작성 가능.

## 4. viewController의 생명주기 (ViewController Life Cycle)

* 핵심 단계: `viewDidLoad` → `viewWillAppear` → `viewDidAppear` → `viewWillDisappear` → `viewDidDisappear`

뷰컨트롤러의 생명주기는 화면이 생성되어 메모리에 올라온 순간부터, 화면에서 사라져 메모리에서 해제되기까지의 각 단계에서 시스템이 자동으로 호출하는 메서드의 흐름을 말한다.<br />
가장 먼저 호출되는 `viewDidLoad`는 뷰컨트롤러의 뷰가 메모리에 로드된 직후에 실행된다. 앱이 실행되는 동안 딱 한 번만 호출되기 때문에, 리소스를 초기화하거나 디자인의 기본 틀을 잡는 등 한 번만 수행하면 되는 작업을 처리하기에 가장 적합한 시점이다.<br />
화면이 실제 사용자 눈에 보이기 직전에는 `viewWillAppear`가 호출된다. 이 단계는 다른 화면에 가려졌다가 다시 돌아올 때마다 매번 실행되므로, 화면이 나타날 때마다 데이터를 새로고침하거나 UI를 최신 상태로 업데이트해야 할 때 사용한다. 이후 화면이 완전히 나타나 사용자와 상호작용이 가능해진 시점에는 `viewDidAppear`가 호출되며, 이때부터 애니메이션을 실행하거나 특정 입력창에 포커스를 주는 작업을 수행한다.<br />
반대로 화면이 사라지기 시작할 때는 `viewWillDisappear`가, 화면이 완전히 사라졌을 때는 `viewDidDisappear`가 순차적으로 호출된다. 이때는 진행 중이던 작업을 멈추거나 데이터를 저장하는 등 정리 작업을 수행한다.<br />
여기서 주의할 점은 **화면 전환 방식(Presentation Style)** 에 따른 차이다. `Full Screen` 방식은 이전 화면을 완전히 덮거나 제거하므로 생명주기 메서드들이 모두 호출되지만, `Sheet` 방식처럼 이전 화면이 아래에 일부 남아있는 경우에는 이전 화면이 완전히 사라진 것이 아니라고 판단하여 생명주기 메서드가 호출되지 않을 수 있다. 따라서 어떤 방식의 전환을 사용하는지에 따라 로직을 배치할 위치를 신중히 결정해야 한다.

* Self: 클래스 내부 프로퍼티를 가리킬 때 사용. 지역 변수와 이름이 같을 때 구분하기 위해 `self.nickname` 이렇게 명시.

## 5. 화면 전환과 Unwind Segue

* Unwind Segue: 쌓인 화면을 탈출하여 이전 화면으로 돌아가는 방법.
* 구현 방법: 돌아가고 싶은(도착지) 컨트롤러에 `@IBAction func unwind...(sender: UIStoryboardSegue)` 코드를 먼저 작성함.
* 주의: 스토리보드에서 끌어서 IBAction을 연결하는 게 아님! 그냥 타자 쳐서 쓰는 것. 그리고 안에는 아무 코드도 짜지 않는다.
* 연결: 스토리보드에서 버튼을 상단의 Exit 아이콘(노랭이 옆옆)으로 드래그하여 연결.
이렇게 하면 fullscreen이었어도 이 unwind 터널을 통해서 화면을 탈출할 수 있고, 또 뜨는 것도 잘 뜨기 때문에 `viewWillAppear`가 뜰 수 있는 것.
